# Widgets in a beamline plugin repository

Reference: `beamline_plugins/debye_bec` (any `*_bec` plugin repo has the same shape).

## Layout

```
<plugin>/
  pyproject.toml
  <plugin>/bec_widgets/__init__.py
  <plugin>/bec_widgets/auto_updates/__init__.py
  <plugin>/bec_widgets/widgets/__init__.py         # empty; discovery walks the package
  <plugin>/bec_widgets/widgets/client.py            # GENERATED by bw-generate-cli --target <plugin>
  <plugin>/bec_widgets/widgets/designer_plugins.py  # GENERATED
  <plugin>/bec_widgets/widgets/<snake_name>/
      __init__.py
      <snake_name>.py                # class PascalName(BECWidget, QWidget)
      <snake_name>.pyproject         # {'files': ['<snake_name>.py']}  -> makes bec-designer see it
      <snake_name>_plugin.py         # QDesignerCustomWidgetInterface (generated once)
      register_<snake_name>.py       # addCustomWidget entry (generated once)
      <snake_name>.ui                # optional, when scaffolded with --use-ui
      <snake_name>_ui.py             # compiled by `bec-plugin-manager edit-ui <snake_name>`
  tests/tests_bec_widgets/conftest.py               # star-imports bec_widgets.tests.fixtures (create it)
  tests/tests_bec_widgets/test_<snake_name>.py
```

## pyproject entry points

```toml
[project.entry-points."bec.widgets.user_widgets"]
plugin_widgets = "<plugin>.bec_widgets.widgets"

[project.entry-points."bec.widgets.auto_updates"]
plugin_widgets_update = "<plugin>.bec_widgets.auto_updates"
```

Exactly one plugin repo may be installed in an environment; `bec_lib.plugin_helper.plugin_package_name()`
resolves it. Widgets whose class name collides with a core `bec_widgets` class are skipped with an
error during generation - pick a distinct name.

## Scaffolding

```bash
bec-plugin-manager create widget <snake_name>            # prompts: use_ui? open_editor?
bec-plugin-manager create widget <snake_name> --no-use-ui --no-open-editor
bec-plugin-manager edit-ui <snake_name>                  # bec-designer + auto-recompile of the .ui
```

It updates the copier answers file, renders the widget package, and commits
`plugin-manager added new widget: <name>`. It requires the plugin repo to be installed and a
clean git state.

## Generate the client

```bash
bw-generate-cli --target <plugin>
```

Writes `<plugin>/bec_widgets/widgets/client.py` (RPC stubs, `_IMPORT_MODULE` per class) and
`designer_plugins.py` (`designer_plugins`, `widget_icons` dicts). The core client merges the
plugin classes at import time, so after installation the widget is available as
`gui.new("<PascalName>")` / `dock.new("<PascalName>")` from the IPython client and in
`bec-designer`.

## Tests in a plugin repo

Use the fixtures bec_widgets ships (>= 3.38) - do not copy `mocked_client` or the leak fixtures
into the plugin, and do not test a hand-built stub instead of the widget to avoid the BEC client.
Put this in `tests/tests_bec_widgets/conftest.py` (the copier template only ships a README there):

```python
from bec_widgets.tests.fixtures import *  # noqa: F401,F403
from bec_widgets.tests.utils import create_widget  # noqa: F401
```

and write tests exactly as in core (`create_widget(qtbot, MyWidget, client=mocked_client)`). Keep
the import in that folder's conftest, not in the repo-wide `tests/conftest.py`, so device and scan
tests do not get the Qt fixtures. Prerequisites (bec_widgets version check, `bec_widgets[dev]` for
pytest-qt/fakeredis, the `QTimer` import-order rule) are in [testing.md](testing.md).
